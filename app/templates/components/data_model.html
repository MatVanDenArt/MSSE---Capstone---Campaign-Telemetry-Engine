The Simulation Funnel

The backend simulation (generator.py) builds synthetic B2B buying journeys using a weighted Markov-style funnel approach.

  1. Top of Funnel (Ad Spend): A simulated user clicks a LinkedIn Ad. This generates a row in linkedin_events with a unique click_id (cookie) and burns ad spend.
  2. Mid Funnel (Website): Moments later, a ga4_events row is created using the exact same cookie_id. If they bounce, the journey ends. If they convert, they provide their email.
  3. Nurture (Email): Over the next 15 days, they receive automated emails, generating mailchimp_events tied to their email address.
  4. Bottom Funnel (Revenue): If engagement is high, they are resolved into crm_users. 30-90 days later, a massive pipeline event is pushed to crm_opps.

Identity Resolution

This application mimics a modern Customer Data Platform (CDP). The hardest problem in marketing telemetry is tying an anonymous click to a $20M closed deal.

// The Identity Chain

1. Anonymous: User has only a cookie_id (LinkedIn -> GA4).

2. Known: User submits a form. GA4 updates with user_id_captured.

3. Resolved: The system queries CRM_USERS on the user_id, matching it to their Mailchimp email, allowing full attribution of the original ad spend.
