The simulation funnel

The backend simulation (generator.py) builds synthetic B2B buying journeys using a weighted Markov-style funnel approach.

  1. Top of funnel (Ad Spend): A simulated user clicks a LinkedIn Ad. Generates a row in linkedin_events with a unique click_id (cookie) and burns ad spend.
  2. Mid funnel (Website): A ga4_events row is created using the same cookie_id. If they bounce, the journey ends. If they convert, they provide their email.
  3. Nurture (Email): Over the next 15 days, they receive automated emails, generating mailchimp_events tied to their email address.
  4. Bottom funnel (Revenue): If engagement is high, they are resolved into crm_users. 30-90 days later, a pipeline event is pushed to crm_opps.

Identity resolution

This application mimics a modern Customer Data Platform (CDP). The hardest problem in marketing telemetry is tying an anonymous click to a closed deal.

// The identity chain

1. Anonymous: User has only a cookie_id (LinkedIn -> GA4).

2. Known: User submits a form. GA4 updates with user_id_captured.

3. Resolved: The system queries CRM_USERS on the user_id, matching it to their Mailchimp email, allowing full attribution of the original ad spend.

Copilot context heuristics

The AI Copilot maintains chat memory during a session, but relies on a backend rule engine to automatically wipe its slate clean when the user shifts to a new investigation, preventing cross-contamination between different targets or campaigns.

// Context breakers (app/api/chat.py)

WIPE CONTEXT: If the prompt starts with major dashboard action triggers (e.g., "review priority action:", "investigate pipeline target:", "generate campaign report").

RETAIN CONTEXT: If the prompt is a conversational follow-up or a direct LLM execution command (e.g., "Execute: /api/draft...").
