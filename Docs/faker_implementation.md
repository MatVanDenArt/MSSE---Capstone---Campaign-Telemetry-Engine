Faker Implementation & Realism Guide
====================================

1\. Execution Speed (How long will it take?)
--------------------------------------------

Generating this data will be **incredibly fast—likely between 1 to 3 seconds** during the FastAPI server startup.

Because we are simulating a targeted B2B ABM campaign (not a massive consumer B2C app), the volume of data is relatively small:

*   15 Accounts \* 40 Users = 600 Core Users.
    
*   90 days of traffic = ~5,000 to 10,000 total event rows across all 4 channels.Python's Faker library, combined with basic memory lists and a final to\_sql Pandas command, will process this volume almost instantly. This ensures your Render free-tier deployment wakes up quickly for your Capstone graders without timing out.
    

2\. The Complexity of Realism
-----------------------------

Setting up basic Faker (getting random names and random dates) is very easy (a 2/10 difficulty). However, making the data _approximate real-world behavior_ is a moderate challenge (a 6/10 difficulty).

If we just use pure randomness, a user might trigger a "Closed Won" CRM event _before_ they ever clicked an ad, which ruins the timeline.

To make it realistic, we will use two specific coding techniques:

### Technique A: Chronological Time Deltas

Instead of picking random dates for every event, we generate a **"Seed Date"** (e.g., the day they clicked a LinkedIn ad). Subsequent events are generated by adding realistic time deltas to that seed:

*   ga4\_visit\_time = linkedin\_click\_time + 2 seconds.
    
*   form\_fill\_time = ga4\_visit\_time + 45 seconds.
    
*   crm\_opp\_time = form\_fill\_time + random(1 to 5 days).
    

### Technique B: Weighted Probabilities

Not all users behave the same way. We will use Python's random.choices(weights=\[...\]) to enforce B2B realities:

*   **Seniority Bias:** A C-Suite user has a 10% chance of clicking an ad, while a Manager/IC has a 60% chance.
    
*   **Bounce Rate:** 50% of GA4 visits will immediately drop off (generating no form fill).
    
*   **The "Trickle" Decay:** When distributing the 90 days of events, we won't distribute them evenly. We will heavily weight the events toward the first 30 days of the campaign, and mathematically decay the probability of clicks as time goes on to simulate the "trickle traffic" we discussed for your completion algorithm.
